# Chaining Commands

## Challenge 1: Chaining with Semicolons

### Problem Statement:
The easiest way to chain commands independent of data transfer is using the `;` operator. Semicolons allow you to pass multiple commands in a single prompt block that execution loops will resolve sequentially once Enter is pressed. In this level, chain `/challenge/pwn` and `/challenge/college` using a semicolon.

### Key Points:
* semicolons decouple command chaining from stdout/stdin data transfer plumbing.
* acts exactly like an inline newline terminator within the shell parser context.

### Command Sequence:
```bash
hacker@dojo:~$ /challenge/pwn; /challenge/college
```

## Challenge 2: Building on Success

### Problem Statement:
The `&&` operator provides conditional chaining based on execution success. The shell parses the exit code of the primary command; if it returns `0` (success), the second command is pulled into the execution thread. Chain `/challenge/first-success` and `/challenge/second` using the `&&` operator.

### Key Points:
* `&&` acts as a logical short-circuit evaluator tracking the process exit status register.
* If `command1` returns a non-zero exit status, `command2` is completely dropped from the execution stack.

### Command Sequence:
```bash
hacker@dojo:~$ /challenge/first-success && /challenge/second
Nice chaining! Flag: pwn.college{gJox5e3JaKlz0llBKZH6nbZ3q9Y.0lM0MDOxwSO2EzNwIzW}
```

## Challenge 3: Handling Failure

### Problem Statement:
The `||` operator acts as a logical fallback control structure. It triggers the execution of the second command *only* if the initial command returns a non-zero exit code (indicating a fault or failure state). Chain `/challenge/first-failure` and `/challenge/second` using `||`.

### Key Points:
* direct logical inverse of the `&&` short-circuit operator.
* indispensable for structural error handling and setting deterministic runtime fallbacks in scripts.

### Command Sequence:
```bash
hacker@dojo:~$ /challenge/first-failure || /challenge/second
Nice chaining! Flag: pwn.college{QDN2aJ0nm14txy53x7pwuG76tAy.01M0MDOxwSO2EzNwIzW}
```

## Challenge 4: Your First Shell Script

### Problem Statement:
Manually processing long sequences of chained operations becomes inefficient. Instead, you can pool linear commands inside a plain text file—a shell script—and run them by executing the file. Write a script named `x.sh` that sequentially invokes `/challenge/pwn` and `/challenge/college`.

### Key Points:
* shell scripts aggregate isolated execution routines into persistent text blocks.
* invoking `bash x.sh` spawns a non-interactive subshell that consumes the target file as a descriptor feed.

### Command Sequence:

## Challenge 6: Executable Shell Scripts

### Problem Statement:

By modifying the target file's metadata to grant execution permissions, the system kernel allows you to invoke the script directly via its relative or absolute file system path. Create a script to run `/challenge/solve`, make it executable, and call it via its path.

### Key Points:
* `chmod` updates the permission bits inside the inode to make the text file natively runnable.

## Challenge 7: Understanding Shebangs

### Problem Statement:
When executing an interpreted script directly from foreign program environments (like a Python process loop), the underlying OS kernel needs an explicit mechanism to resolve what binary should read the text context. ### Key Points:
* the kernel opens the binary file descriptor, reads the initial magic bytes (`#!`), and calls the specified interpreter path with the script path as an argument.
* zero tolerance formatting: no whitespace blocks or empty rows are permitted prior to the shebang definition.

### Command Sequence:

### Key Points:
* every distinct `elif` condition loop requires its own explicit `then` keyword mapping.

### Command Sequence:

```bash
    echo "college"
```
